# Contributing

Thank you for helping document the software that runs African energy.

## Ways to contribute

- Suggest a new product or organisation.
- Add or correct a deployment.
- Provide a stronger or more independent source.
- Report a renamed, acquired, inactive, or duplicated record.
- Improve the taxonomy, documentation, accessibility, or tooling.

The easiest route is an appropriate GitHub issue form. Technical contributors
may open pull requests.

## Evidence expectations

Every material claim needs a source. A product website may support product
description and availability, but it does not independently verify a deployment.
For deployment verification, prefer customer, utility, regulator, procurement,
funder, or official programme sources.

Read the [evidence and verification policy](docs/04-evidence-and-verification-policy.md)
before submitting data.

## Data pull requests

Data pull requests must:

- use stable project IDs;
- identify every changed entity;
- add assertion-level sources;
- distinguish provider claims from independent evidence;
- disclose the contributor's relationship to the subject;
- avoid confidential or security-sensitive information;
- pass repository validation; and
- remain small enough for meaningful human review.

## Editorial independence

Payment, sponsorship, employment, investment, or partnership does not guarantee
inclusion, classification, verification, ranking, or removal.

## Contributor conduct

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md).
